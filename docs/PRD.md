## 1. 개요

**PRX-917**은 인터넷·기지국 없이 두 기기가 직접 통신하는 **1:1 종단간 암호화 텍스트 무전기**다.
폰 앱(Android/iOS)으로 먼저 구현하고, 장기적으로 LoRa(917–923.5MHz) 전용 핸드셋으로 확장한다.

### 1.1 문제

- 재난·산악·해상·통신 장애 상황에서는 일반 메신저가 동작하지 않는다.
- 기존 오프그리드 무전/메시징 도구는 평문이거나, 키 검증 절차가 없어 도청·사칭에 취약하다.
- 군용 보안 무전기는 일반인이 쓸 수 없고, 쓰기도 어렵다.

### 1.2 제품 비전

> "무전기처럼 쉽게, 메신저보다 안전하게." — 채널을 고르고 호출하면, 도청·변조·사칭이 불가능한 대화가 열린다.

## 2. 목표와 비목표

### 2.1 목표

| ID | 목표 | 측정 기준 |
|---|---|---|
| G1 | 인프라 없이 통신 | 비행기 모드 + Wi-Fi/BT만 켠 상태에서 두 기기 교신 성공 |
| G2 | 도청·변조 불가 | 모든 페이로드가 AEAD 암호문, 변조 프레임 100% 거부 |
| G3 | 전방향 비밀성 | 메시지마다 래칫 키 교체 (vodozemac Olm) |
| G4 | 중간자 방어 | 안전번호 대조 전에는 "미검증" 상태가 항상 표시됨 |
| G5 | 기기 분실 대비 | 신원키는 생체/기기 인증 없이는 복호화 불가 |
| G6 | 쉬운 사용 | 첫 실행부터 첫 메시지까지 3분 이내, 5단계 이내 |

### 2.2 비목표 (이번 범위에서 하지 않음)

- 그룹 채팅, 메시 릴레이(다중 홉)
- 음성 통화 / PTT 음성
- 메타데이터 은닉(송수신 사실 자체 숨기기), 전파 방해(jamming) 대응
- 군용 장비의 분석·복제, 주파수 도약 모방
- 핵심 암호 알고리즘 자체 구현 (감사된 라이브러리만 사용)

## 3. 대상 사용자

| 페르소나 | 상황 | 핵심 니즈 |
|---|---|---|
| 아웃도어 팀 (등산·캠핑·해상) | 통신 음영 지역에서 동행 간 연락 | 오프라인 동작, 배터리, 간단한 조작 |
| 재난 대응 자원봉사자 | 기지국 장애 시 현장 조율 | 빠른 페어링, 신뢰할 수 있는 상대 확인 |
| 프라이버시 중시 사용자 | 민감한 대화를 서버 없이 | 종단간 암호화, 기록이 남지 않음 |
| 보안·암호 학습자 | Double Ratchet 실전 구조 학습 | 투명한 설계, 오픈소스 |

## 4. 핵심 사용 흐름

```
① 잠금 해제   생체인증(실패 시 기기 암호) → 신원키 복호화
② 채널 선택   CH 1~8 (= 통신망). 같은 채널끼리만 서로 발견
③ 탐색/호출   주변 국 자동 발견 → 상대 선택 또는 수신 호출 수락
④ 안전번호    양 기기의 숫자를 대조 → "일치·확인"
⑤ 교신        암호 채팅. 링크가 끊기면 재연결
```

보조 흐름: QR로 신원 교환(페어링 탭), 설정(콜사인·채널·생체잠금·자동삭제·알림음·신원키 재생성).

## 5. 기능 요구사항

우선순위: **P0** = 출시 필수 · **P1** = 출시 목표 · **P2** = 이후

### 5.1 보안 코어 (`crypto_core`)

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| F-C1 | 기기당 장기 신원키(X25519) 생성 | P0 | ✅ |
| F-C2 | 프리키 발행 · 세션 수립(X3DH) · Double Ratchet 암복호화 | P0 | ✅ |
| F-C3 | 안전번호 생성 (5자리 × 3블록, 양측 동일) | P0 | ✅ |
| F-C4 | 신원·세션의 암호화 pickle 저장/복원 | P0 | ✅ |
| F-C5 | UniFFI Swift/Kotlin 바인딩 | P0 | ✅ |
| F-C6 | 재전송·순서 뒤바뀜 프레임 처리 (래칫 카운터 기반 거부/수용) | P1 | ✅ 재전송 거부·순서 뒤바뀜 수용·변조 거부·연속 PreKey 테스트 (crypto_core 27건) |

### 5.2 키 보호 · 잠금

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| F-K1 | 신원키는 OS 보안저장소(Android Keystore / iOS Keychain)에 봉인 | P0 | ✅ 코드 (실기기 미검증) |
| F-K2 | 봉인 키는 **사용자 인증과 암호학적으로 결합** (Android `CryptoObject`, iOS `SecAccessControl`) — UI만의 잠금 금지 | P0 | ✅ 코드 (실기기 미검증) |
| F-K3 | 생체인증은 강한 등급(BIOMETRIC_STRONG / Face ID·Touch ID), 대체 수단은 기기 암호 | P0 | ✅ (Android API 24–29는 생체만) |
| F-K4 | 생체/잠금화면이 미설정이면 잠금 해제 불가 + 설정 안내 (무인증 통과 금지) | P0 | ✅ |
| F-K5 | 생체 등록 변경 시 키 무효화 → 신원 재생성 안내 | P1 | Android ✅ · iOS는 암호 대체 정책상 해당 없음 |
| F-K6 | 앱 백그라운드 진입 후 30초 경과 시 재잠금(신원·세션·대화 메모리 폐기), 앱 전환기 화면 가림 | P1 | ✅ 코드 (실기기 미검증) |

### 5.3 연결 · 교신

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| F-T1 | 채널(CH 1~8)별 광고·탐색, 채널 전환 시 재시작 | P0 | ✅ (플랫폼별) |
| F-T2 | 피어 발견 시 신원 공개키 교환 → 안전번호 표시 | P0 | ✅ |
| F-T3 | 안전번호 확인 전 "미검증" 상태 상시 표시, 확인 여부를 상대 신원별로 저장 | P0 | ✅ Android·iOS — (내 키\|상대 키) SHA-256 저장, 검증 상대는 재확인 생략, "✓ 검증됨/미검증" 배지, 설정에서 기록 삭제 |
| F-T4 | 연결 끊김 감지 및 재연결 | P0 | Android ✅ · iOS 확인 필요 |
| F-T5 | **Android ↔ iOS 상호 통신** (공통 BLE GATT 전송) | P1 | 미착수 |
| F-T6 | 메시지 전달 확인(ACK) 및 미전달 표시 | P1 | ✅ Android·iOS — 안쪽 평문 `M`+id/`A`+id, 10초 무응답·끊김 시 미전달, 수신 id 중복 제거 (실기기 미검증) |
| F-T7 | 이전에 검증한 상대와는 세션을 복원해 재검증 없이 교신 | P1 | ✅ Android·iOS — 래칫 상태는 디스크에 저장하지 않고 연결마다 새 세션(X3DH)을 수립(전방 비밀성 유지), 검증 기록(F-T3)으로 재확인 생략. initiator 가 세션 개시 신호(`S`)를 즉시 보내 양쪽 모두 바로 송신 가능, 세션 수립 전 송신은 미전달 표시 |

### 5.4 페어링 · 설정 · UI

| ID | 요구사항 | 우선순위 | 상태 |

## 6. 비기능 요구사항

| 분류 | 요구사항 |
|---|---|
| 보안 | 핵심 암호는 vodozemac 등 감사된 라이브러리만 사용. 저장소에 비밀값 금지. 로그에 평문·키 출력 금지 |
| 개인정보 | 서버 없음. 메시지는 기기에만 저장, 자동삭제 지원. 분석·추적 SDK 미탑재 |
| 성능 | 같은 공간(10m 이내)에서 메시지 왕복 지연 1초 이내, 발견→연결 10초 이내 |
| 신뢰성 | 연결 끊김 후 재연결 시 세션 유지, 메시지 유실 시 사용자에게 표시 |
| 배터리 | 대기(광고·탐색) 1시간 소모 5% 이하 목표 |
| 규정 | LoRa는 국내 ISM 대역·출력·점유시간 규정 준수. 앱스토어 암호화 수출 규정 신고 |
| 플랫폼 | Android 7.0(minSdk 24) 이상, iOS 15 이상 |
| 품질 | `crypto_core` 테스트 전부 통과, CI에서 Android APK·iOS 시뮬레이터 빌드 통과 |

## 9. 성공 지표

- 첫 실행 → 첫 메시지 소요 시간 (목표 3분 이내)
- 안전번호 확인 완료율 (목표: 교신 세션의 90% 이상)
- 메시지 전달 성공률 (목표 99% 이상, 연결 유지 상태 기준)
- 보안 점검에서 치명적 결함 0건

| BLE 처리량·MTU 한계 | 크로스플랫폼 메시지 지연·분할 필요 | 프레임 분할/재조립 규격 설계, 텍스트 전용 유지 |

| 무선 규정 위반 | 법적 문제 | 하드웨어 단계에서 인증 절차 선행 |

## 11. 미결 사항

1. 메시지 기록 보관 정책 기본값 (보관 안 함 / 24시간 / 무기한)
2. 신원 재생성 시 기존 검증 상대에게 알리는 방법
3. 채널 수(현재 8개) 확장 여부
4. iOS 실기기 테스트용 Apple 개발자 계정 준비 여부
5. 크로스플랫폼 전송을 BLE 직접 구현으로 할지, Wi-Fi Aware 등 대안을 검토할지
