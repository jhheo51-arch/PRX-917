# PRX-917 실기기 테스트 체크리스트 (M2 · M3)

PRD의 M2(실기기 검증), M3(신뢰성)를 완료로 표시하기 위한 수동 테스트 목록입니다.
각 항목을 기기 2대로 실행하고 결과 칸에 `✅` / `❌` / `–`(해당 없음)를 적습니다.
실패하면 [결과 기록](#결과-기록)에 기기, OS 버전, 재현 절차, 화면/로그를 남깁니다.

- 관련 문서: [PRD](PRD.md) · [사용 가이드](USER_GUIDE.md)
- 기호: **A** = 기기 A(연결을 거는 쪽이 되기 쉬움), **B** = 기기 B

---

## 0. 준비

### 기기

| 플랫폼 | 필요 | 비고 |
|---|---|---|
| Android | 2대, Android 7.0(API 24) 이상 | 가능하면 API 30+ 1대, API 24–29 1대 (생체/암호 대체 동작이 다름) |
| iOS | 2대, iOS 15 이상 | Mac + Xcode 16, Apple ID 개발 서명 (무료 계정은 7일마다 재설치) |

> Android ↔ iOS는 아직 서로 통신할 수 없습니다(M4). **같은 플랫폼끼리** 테스트합니다.

### 설치

**Android**
```bash
cd apps/android && ./gradlew assembleDebug
adb -s <기기A> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <기기B> install -r app/build/outputs/apk/debug/app-debug.apk
```

**iOS** (Mac에서)
```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
bash apps/ios/scripts/build-xcframework.sh   # crypto_core → xcframework
cd apps/ios && xcodegen generate && open PRX917.xcodeproj
# Signing & Capabilities → Team 선택 → 실기기 선택 후 Run
# 기기: 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 신뢰
```

### 공통 사전 조건
- 두 기기 모두 **화면 잠금(PIN/암호)과 생체인증 등록** 완료
- 블루투스·Wi-Fi 켬 (인터넷 연결은 필요 없음), 위치(Android) 켬
- 두 기기를 1~3m 거리에 둠
- Android 로그 확인용: `adb logcat | grep -i prx917`

## 3. 신뢰성 (M3 · F-T3 · F-T4 · F-T6 · F-T7)

| ID | 절차 | 기대 결과 | Android | iOS |
|---|---|---|---|---|
| R-01 | F-04 이후 양쪽 앱 재실행 → 같은 채널 재연결 | 안전번호 화면 **없이** 바로 채팅, `✓ 검증됨` | | |
| R-02 | R-01 직후 **양쪽 모두** 바로 메시지 전송 | 양방향 모두 `✓ 전달` | | |
| R-03 | 연결 직후 1초 안에 전송 | 전달되거나 `! 미전달` 표시 (조용히 사라지면 실패) | | |
| R-04 | 설정 → "검증한 상대 기록 지우기" 후 재연결 | 안전번호 화면 다시 표시, `미검증`(빨강) | | |
| R-05 | B에서 신원키 재생성 후 A와 재연결 | 양쪽 모두 안전번호 화면 다시 표시 (A의 기록에도 B의 새 키는 없음) | | |
| R-06 | 대화 중 B의 비행기 모드 켬 → A가 전송 | A: `! 미전달` (10초 이내 또는 끊김 감지 즉시), 링크 끊김 표시 | | |
| R-07 | R-06 후 B 비행기 모드 끔 → 재연결 → A가 재전송 | 재연결 성공, `✓ 전달` | | |
| R-08 | 두 기기를 서서히 멀리 (10m → 30m → 벽 너머) | 끊긴 거리 기록, 끊기면 미전달 표시 | | |
| R-09 | B를 백그라운드로 보냈다가 20초 내 복귀 | 연결/세션 유지 여부 기록 (OS가 끊을 수 있음) | | |
| R-10 | 빠르게 10개 연속 전송 | 10개 모두 순서대로 1번씩 표시, 모두 `✓ 전달` | | |
| R-11 | 설정 "24h 자동 삭제" 켬 + 기기 시간을 25시간 뒤로 변경 → 1분 대기 | 이전 메시지 삭제 (확인 후 시간 원복) | | |
| R-12 | 수신 알림음 켬/끔 | 켬: 수신 시 소리 / 끔: 무음. ACK에는 소리 없음 | | |

## 4. 성능 측정 (PRD 6장 목표)

같은 방, 2m 거리에서 5회 측정해 평균을 기록합니다.

| 항목 | 목표 | 측정 방법 | Android | iOS |
|---|---|---|---|---|
| 발견 → 연결 | 10초 이내 | 채널 선택 순간부터 안전번호/채팅 화면까지 스톱워치 | | |
| 메시지 왕복 | 1초 이내 | 전송 탭 → `✓ 전달` 표시까지 | | |
| 대기 배터리 | 1시간 5% 이하 | 탐색 화면에 1시간 둔 뒤 배터리 % 차이 (화면 꺼짐 금지 설정 해제) | | |

## 완료 판정

- **M2 완료:** 1·2장 전 항목과 4장의 "발견 → 연결", "메시지 왕복"이 플랫폼별로 통과 (`–` 제외)
- **M3 완료:** 3장 전 항목 통과
- 통과하면 PRD 해당 요구사항의 "(실기기 미검증)"을 지우고 날짜를 적습니다.

## 결과 기록

### 2026-10-17 · 1차 (Android 에뮬레이터 2대, 실기기 아님)

환경: Android 14(API 34) Google Play 이미지 2대, 같은 PC, Nearby는 가상 BT/Wi-Fi 경유. 생체 대신 PIN 사용.

| 결과 | 항목 |
|---|---|
| ✅ 통과 | K-01, K-02, K-04, K-06, K-08, K-09, K-11(화면 캡처가 빈 이미지), F-01, F-03, F-04, F-06, F-07, F-09, F-10, R-01, R-04, R-06, R-07, R-10 |
| 측정 | 발견 → 연결 6~16초(에뮬레이터), 메시지 왕복 1~2초 내 `✓ 전달` |
| – 미실시 | K-03·K-05·K-07(지문), K-10(눈으로 확인 필요), K-12, F-02, F-05, F-08(adb로 한글 입력 불가), F-11, R-02·R-03·R-05·R-08·R-09·R-11·R-12, 배터리 |

발견·수정한 버그
- **연결 충돌로 영구 "발견" 상태**: 양쪽이 동시에 `requestConnection` → Nearby 충돌 처리로 둘 다 닫히고 재시도 없음.
  → 신원키가 작은 쪽만 먼저 요청, 큰 쪽은 8초 뒤 대체 요청, 실패 시 1.5~3.5초 백오프 재시도(최대 10회).
- **끊긴 뒤 보낸 메시지가 10초간 "전송 중"**: 링크가 끊긴 상태면 즉시 `! 미전달` (Android·iOS).

참고: 재연결 1회가 Nearby의 Wi-Fi 승격 실패(`ESTABLISH_CONNECTION_FAILED`, 에뮬레이터 가상망)로 곧 끊겼고, 재시도에서는 정상. 실기기에서 R-07을 다시 확인할 것.
